# QQ companion memory and proactive messages

The owner-only Character page stores relationship (`none`, `daughter`, `wife`, `mother`) and a 0–100 proactivity preference alongside the existing persona. A zero proactivity setting stops scheduled sends. Each QQ C2C recipient has separate memory, intimacy statistics, and daily quota; group chats do not enter this feature.

Intimacy is an engagement score, not a model confidence or a claim about a human relationship. It uses successful chat turns and active days: `round(100 * (1 - exp(-(.09 * days + .015 * min(effectiveTurns, 200)))))`, with at most 20 effective turns per day. Failed or unsolicited messages do not raise it.

Memory extraction runs through the existing DeepSeek agent after the first successful private chat, then after four new turns or six hours, and before the nightly plan. Only explicit stable user facts backed by a literal quote and a real message ID are accepted. Stored facts and decisions are encrypted with the existing day-task cipher. The UI shows keywords with source quotes in tooltips. Clearing memory also cancels pending sends and ignores older messages on future extraction. It does not delete the original chat history or engagement statistics.

One process-level scheduler checks every 30 seconds. In Asia/Shanghai it makes one durable plan per recipient per day beginning at 01:00. The first installation waits for the next 01:00; later restarts can recover the current day's plan. JEV (the configured local Laya service) scores candidate counts 0–3 using binary choices. The count distribution is weighted by proactivity and intimacy, then sampled; higher values increase the probability of larger counts. JEV also ranks five spaced slots: 09:30, 11:30, 14:30, 17:30, 20:00. A missing service waits 15 minutes before retrying, without inventing model scores.

At each slot DeepSeek uses the current persona, memory and recent private chat to write a short message. Delivery respects text/voice preference; short auto replies use the existing local expression selector. One slot produces one platform message, without extra sticker or text supplements. Three **attempts** per recipient per local day is a hard limit, including uncertain or failed attempts. Sends are restricted to 09:00–21:00 and expire after a 45-minute delay. Disabling proactivity, unlinking the recipient or clearing memory during generation stops the send. An uncertain delivery is never automatically repeated; failure cancels the rest of that day's messages.

For replies to inbound QQ chats, JEV decides sticker suitability independently from text/voice delivery. It classifies the current user message and answer as emotional chat or task-oriented communication; affectionate previous turns do not enter this suitability decision. Only an `add` decision with confidence at least 0.60 enters the owner's sticker-probability draw. Even 100% probability cannot override a formal/task decision. Voice preference and persona intimacy do not grant sticker eligibility. The existing recent context remains available for choosing an image after eligibility; `__none__` is a valid choice when installed images do not fit. Missing, invalid or timed-out decisions and selections skip the optional image instead of choosing a random fallback. Primary answer delivery still precedes image selection. Suitability scores, probability skips and actual delivery remain in the existing private decision record, never in chat text.

The implementation uses the official C2C active-message endpoint with no `msg_id`, `event_id` or `is_wakeup`, and never borrows an old reply ID. QQ can reject active delivery when users disallow it. See [QQ message overview](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/overview.html) and [C2C message API](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_users_user_openid_messages.post.html).

`VEYA_QQ_COMPANION_SCHEDULER=0` disables the scheduler for non-delivery environments. The local endpoint follows `QQ_EXPRESSION_URL` / `LAYA_DECISION_URL`, using the same configured model as the existing QQ expression router. Verification uses simulated clocks and mocked platform sends; it does not send test messages to real users.
